# Product Inventory Management

Upload a product spreadsheet (Excel or CSV), have every row validated, and browse the result on a
dashboard with a sortable, paginated table, stock age, and an inventory summary.

Built for the ABLSoft Full-Stack Developer technical test.

| Part | Stack | Details |
| --- | --- | --- |
| [`backend/`](backend/README.md) | Java 25 · Spring Boot 4.1 · PostgreSQL 18 | Import pipeline and REST API |
| [`frontend/`](frontend/README.md) | Angular 21 · nginx | Dashboard: table, summary panel, import dialog |

---

## Quick start

**You need:** [Docker Desktop](https://www.docker.com/products/docker-desktop/) on Windows or macOS,
or Docker Engine with the Compose plugin on Linux. You do **not** need Java, Maven, Node or
PostgreSQL. They all run inside containers.

```bash
git clone https://github.com/preet-git/inventory-application.git inventory-app
cd inventory-app
docker compose up --build -d
```

The command returns once all three containers are up. The first run downloads base images and
dependencies and takes a few minutes; later runs start in seconds. Then open:

| Address | What |
| --- | --- |
| **http://localhost:8081** | The dashboard |
| http://localhost:8080/api | The REST API |
| `localhost:5433` | PostgreSQL, for a DB tool (database `inventory`, user and password `postgres`) |

| To… | Run |
| --- | --- |
| Watch the logs | `docker compose logs -f` |
| Check health | `docker compose ps` (the API and database should show `healthy`) |
| Stop, keeping imported data | `docker compose down` |
| Stop and delete all data | `docker compose down -v` |

Use `docker compose` with a space. The retired `docker-compose` (v1) cannot build these images.

## Using the app

1. Click **Import Data**, then choose or drag in a `.xlsx`, `.xls` or `.csv` file of up to **50 MB**.
2. The dialog shows rows read, imported and rejected as the import runs, then the result.
3. The table and summary refresh. The row numbers of any rejected rows stay listed in the
   right-hand panel.

### File format

The file needs a header row with these six columns. The rules for matching the header are:

- Column order doesn't matter.
- Matching ignores case and extra spaces.
- Any other columns are ignored.
- The header can sit anywhere in the first 20 non-blank rows.
- In a workbook, the first sheet that has a header is imported.

| Column | Rules |
| --- | --- |
| Product SKU | Required, up to 64 characters. Stored upper-case, so `abc-1` and `ABC-1` are the same SKU |
| Product Name | Required, up to 255 characters |
| Category | Required, up to 255 characters |
| Purchase Date | Required. Real Excel date cells, or text such as `2024-03-15`, `03/15/2024`, `15-03-2024`, `15 Mar 2024`, `March 15, 2024` |
| Unit Price | Required, zero or more. A leading or trailing `$ £ € ₹ ¥` and grouping like `1,234.56` are accepted. Stored to 2 decimals |
| Quantity | Required whole number above zero |

Ambiguous dates are read month-first: `03/04/2024` is 4 March 2024, not 3 April. A date that only
makes sense day-first, such as `15/03/2024`, is read as 15 March 2024. CSV files must be saved as
UTF-8.

### How problems are handled

Problems are caught at three levels, and a bad row never stops the rest of the file:

| Level | What you see | Examples |
| --- | --- | --- |
| The upload | Refused straight away, with a message in the dialog | Not a `.xlsx`, `.xls` or `.csv`; contents that don't match the extension; an empty file; over 50 MB; too many imports already running |
| The whole file | The import ends as **Failed**, with a message | No header row (the message lists the missing columns); a CSV not saved as UTF-8; a workbook whose formulas were never calculated |
| A single row | That row is rejected; everything else imports | A missing or invalid value; a formula that evaluates to an error; the same SKU and Purchase Date twice in one file |

**Duplicates.** A Product SKU + Purchase Date pair is unique, enforced by a database constraint.

- **Within one file,** the first occurrence is imported and any repeat is rejected.
- **Across imports,** a pair that is already in the database from an earlier import is **updated**
  rather than duplicated. Re-importing a corrected file therefore fixes rows in place.

**Formulas.**

- **In `.xls` files,** formulas are evaluated by Apache POI.
- **In `.xlsx` files,** each formula's result as saved by Excel is used. These files are streamed
  row by row to keep memory flat, and Excel always stores the result with the formula.
- **A formula whose result is an error,** such as `#DIV/0!` or `#REF!`, rejects its row. The reason
  names the formula.
- **A file whose formulas were never calculated** (typical of files generated by other tools) is
  rejected as a whole, with instructions to open and re-save it in Excel.

**Why was a row rejected?** The dashboard lists rejected row numbers, and the reasons are stored in
the database. To see them for the most recent import:

```bash
docker compose exec db psql -U postgres -d inventory -c "SELECT row_number, reason FROM import_rejection WHERE import_id = (SELECT max(id) FROM import_run) ORDER BY row_number;"
```

If you changed `DB_USER` or `DB_NAME`, adjust `-U` and `-d` to match.

| Requirement from the brief | How it is met |
| --- | --- |
| Read an Excel file with the six columns | `.xlsx` and `.xls` (plus `.csv`); columns found by header name, in any order |

| Prominent Import Data button | Top right of the dashboard |
| Summary card: total products, total inventory value (Unit Price × Quantity), average stock age | Right-hand panel |

## Configuration

Nothing needs configuring. Every setting has a default in `docker-compose.yml`, and no `.env` file
is required. To change a setting, copy `.env.example` to `.env` and edit it.

| Variable | Default | What it controls |
| --- | --- | --- |
| `DASHBOARD_PUBLISHED_PORT` | `8081` | Host port for the dashboard |
| `DB_PUBLISHED_PORT` | `5433` | Host port for PostgreSQL. Not 5432, so it won't clash with a local install |
| `DB_NAME` / `DB_USER` / `DB_PASSWORD` | `inventory` / `postgres` / `postgres` | Database credentials, given to both the database and the API |
| `CORS_ALLOWED_ORIGINS` | `http://localhost:8081,http://127.0.0.1:8081,http://localhost:4200` | Web pages allowed to call the API |

- **The API always uses host port 8080.** The dashboard has `http://localhost:8080/api` built in.
- **If you change `DASHBOARD_PUBLISHED_PORT`,** add the new address to `CORS_ALLOWED_ORIGINS`.
- **The `DB_*` values are only read on the first start.** After changing them, run
  `docker compose down -v` (this deletes imported data) and start again.
- **`postgres` is a fine password on a laptop.** Set a real one anywhere shared.

## How it fits together

```
                 page (static files)
  Browser ─────────────────────────────▶  frontend   nginx         host port 8081
     │
     │           API calls (JSON, file upload)
     └─────────────────────────────────▶  backend    Spring Boot   host port 8080
                                              │
                                              │  private Docker network
                                              ▼
                                           db         PostgreSQL    host port 5433
```

Three containers share one private network. The browser loads the dashboard from port 8081 and
calls the API directly on port 8080, which the API's CORS settings permit. Inside Docker, the API
reaches PostgreSQL by its service name, `db`.

Start-up order is enforced with health checks:

1. **db** starts. On the very first run, it creates the database and user from the `DB_*` values.
2. **backend** waits for `db` to be healthy. It then runs the Flyway migrations, which create all
   the tables, and reports healthy once it can answer a query.
3. **frontend** waits for `backend` to be healthy, so the dashboard never loads without an API
   behind it.

Imported data lives in the `db-data` volume, so it survives restarts until `docker compose down -v`.

## Troubleshooting

| Symptom | Cause and fix |
| --- | --- |
| `port is already allocated` | Another program uses 8080, 8081 or 5433. Stop it, or move the dashboard or database port in `.env`. Port 8080 must be free |
| Dashboard says *Cannot reach the API* | The API isn't up. `docker compose ps` should show it `healthy`; if not, `docker compose logs backend` says why |
| CORS error in the browser console | The dashboard was opened from an address not in `CORS_ALLOWED_ORIGINS`. Use http://localhost:8081, or add yours |
| `password authentication failed` in the backend log | The `DB_*` values changed after the database was created. Run `docker compose down -v`, then start again |
| `the --mount option requires BuildKit` | The old `docker-compose` was used. Run `docker compose` instead |
